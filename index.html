              Spatial interfaces · Self-initiated concept

              What this prototype tests

              Spatial AI lets people change a 3D space by speaking and pointing, as in Bolt's "put that there" (1980). The hard part isn't understanding the words. It's making sure the person knows what the system thinks "that" and "there" mean before it acts, and that they can stop it or take it back. Guidelines for human-AI interaction ask systems to make clear what they can do, to support efficient correction, and to narrow the scope of what they do when in doubt (Amershi et al., 2019). Mixed-initiative design adds that an agent should weigh the cost of acting against the cost of asking (Horvitz, 1999). This room puts those rules into practice.

              Three agents, one contract

              Each request passes through three agents. You can open their messages under "Agent trace" on every preview.

              AgentIts jobWhat it may not do
              Language agentTurns what you said into an action, an object and a placeGuess which object you mean when there's more than one; it asks a numbered question
              Spatial agentWorks out where "there", "next to the sofa" or "the corner" is, in metersUse a spot you haven't marked; if you say "there" with nothing marked, it asks you to point
              Layout checkerChecks for overlaps and walls, and nudges a placement when neededNudge anything without saying how far and why
              Kind of changeWhat happens
              Add, move, turn, resize, recolorA purple preview shows the result for 1.6 seconds, then it applies. Undo takes it back.
              RemoveThe object turns red and waits for your OK.
              Agent suggestions ("tidy up")Each suggestion has a reason and a checkbox. Nothing applies until you choose. Suggestions that add furniture start unchecked.
              Unclear which objectA numbered question, with the numbers shown in the room
              StopCancels any preview and question, and turns the microphone off. Nothing changes.

              The usability test

              Five tasks cover the riskiest moments: placing by reference, pointing, a removal that needs an OK, recovering with undo, and reviewing agent suggestions. For each task the test records completion, time, the number of commands, clarifying questions, misunderstood requests, stops and undos. After each task it asks one question: how easy was it, on a 7-point scale. That is the Single Ease Question, which performs as well as longer post-task questionnaires (Sauro & Dumas, 2009). Results export as CSV or JSON and never leave the browser.

              For agents

              The room is usable by software too, not just by people. An agent can drive it through window.SpatialDirector and read the scene as data. The same contract applies: a removal or suggestion called through the API still waits for confirm().

              SpatialDirector.run("put a lamp next to the sofa")  // returns what the agents understood
SpatialDirector.point(x, z)   // mark a spot, in meters from the room's center
SpatialDirector.confirm()     // approve a change that is waiting for an OK
SpatialDirector.answer(1)     // answer a numbered question
SpatialDirector.stop()        // cancel everything pending
SpatialDirector.undo()
SpatialDirector.state()       // the scene as JSON (below)
